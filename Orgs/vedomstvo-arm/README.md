# АРМ специалиста ведомства — интерактивный прототип

Кликабельный прототип автоматизированного рабочего места (АРМ) специалиста
ведомства для платформы **eKhizmat** (Единый портал госуслуг). Реализует
требования раздела **7Б** технического задания (`ТЗ_eKhizmat_Единый_портал_госуслуг.docx`).

Без бэкенда, без React и сборки — чистые **HTML + CSS + JS**. Всё состояние
живёт в браузере (in-memory + `localStorage`), поэтому прототип ведёт себя как
настоящий продукт: заявления меняют статусы, тикают сроки (SLA), приходят
уведомления, формируются подписанные результаты.

Визуальный слой полностью взят из приложенной **дизайн-системы**
(`../design-system-ekhizmat`): токены, компоненты, иконки. Ни одного «сырого»
цвета — только переменные системы.

## Как открыть

Проще всего — через локальный сервер (спрайт иконок встроен в страницу, но
дизайн-система подключается по относительному пути к соседней папке):

```bash
cd /Users/osimij/Desktop/Orgs
python3 -m http.server 8477
```

Открыть: <http://localhost:8477/vedomstvo-arm/index.html>

Файл `index.html` также открывается двойным кликом (`file://`) — иконки
встроены, CSS подтягивается по относительному пути.

### Вход (демо)
Логин и пароль уже подставлены → **Продолжить** → код МФА подставлен → **Войти**.
Тумблеры темы (луна/солнце) и языка (🌐 ru↔tg) — в правом верхнем углу.
Меню специалиста (аватар) → «Сбросить демо-данные» вернёт исходное состояние.

## Что реализовано (карта на §7Б ТЗ)

| Требование ТЗ | Где в прототипе |
|---|---|
| **7Б.4** Вход по усиленной аутентификации (МФА) | Экран входа: логин/пароль → OTP-код |
| **7Б.2** Очередь заданий (сортировка по SLA и приоритету; фильтр по услуге и статусу) | «Мои задания»: метрики, фильтры, сортируемые колонки |
| **7Б.2** Карточка заявления (все данные, документы, межвед-сведения, история) | Вкладки: Обзор · Документы · Межвед. сведения · История |
| **7Б.2** Запрос сведений через Smart Bridge из карточки | «Запросить сведения» → выбор типа/ведомства → ответ приходит асинхронно |
| **7Б.2** Возврат на уточнение → статус «Требует уточнения» | «Вернуть на уточнение» (обоснование обязательно) |
| **7Б.2** Принятие решения с обязательным обоснованием; критичные — «четыре глаза» | Модал решения → для критичных услуг шаг подтверждения вторым специалистом |
| **7Б.2** Формирование результата + подпись ЭЦП | После решения: панель «Результат» с макетом документа и подписью ЭЦП |
| **7Б.2 / 7Б.3** Контроль сроков (норма/приближение/нарушение) + эскалация | Живой SLA-индикатор в списке и кольцо в карточке; экран «Просроченные»; уведомления об эскалации |
| **7Б.2** Массовые операции для однотипных заявлений | «Массовая обработка»: выбор услуги → пакетное решение |
| **7Б.3 → §14** Метрики нарушений SLA по специалистам | «Отчётность»: сводка + таблица соблюдения SLA |
| **7.2** Статусная модель (10 статусов) | `js/data.js` → `STATUS`; статус-пилюли на всех экранах |
| **7Б.4** Специалист видит заявления своего ведомства; журнал аудита (WORM) | Ведомство «Министерство юстиции»; вкладка «История» = неизменяемый журнал |
| **6В.2** Многоязычность tg/ru без перезагрузки | Тумблер языка 🌐 — весь интерфейс переключается мгновенно |
| **6В.1 / 6Б.2** Доступность, адаптивность, mobile-first | Клавиатура/фокус из дизайн-системы; адаптив от мобильного до десктопа |

## Структура

```
vedomstvo-arm/
├── index.html      ← точка входа; спрайт иконок встроен; подключает дизайн-систему
├── css/app.css     ← прикладной слой: шелл, очередь, карточка, отчётность (только токены)
├── js/data.js      ← модель данных (Минюст), статусная модель §7.2, словарь ru/tg §6В.2
└── js/app.js       ← роутинг, живые SLA-таймеры, переходы состояний, модалы, тосты
```

Дизайн-система подключается из `../design-system-ekhizmat/css/` — единый
источник токенов и компонентов, прототип его не дублирует.

## Заметки
- Это **прототип интерфейса**, а не система: Smart Bridge, платежи, BPM и ЭЦП
  имитируются на клиенте (таймеры/заглушки), реального обмена нет.
- Данные вымышленные; ведомство, услуги и заявители — демонстрационные.
