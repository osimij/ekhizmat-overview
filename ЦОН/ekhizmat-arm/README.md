# eKhizmat — АРМ оператора ЦОН

Фронтенд рабочего места оператора. Чистый HTML/CSS/JS, без сборщиков и фреймворков.
Единый источник правды по требованиям — [`../ARM-OPERATOR-UI-PLAN.md`](../ARM-OPERATOR-UI-PLAN.md).
Ссылки вида «§4.3» ниже — разделы этого плана.

## Запуск

```bash
python3 -m http.server 8412
```

- Приложение: <http://localhost:8412/index.html>
- Витрина компонентов: <http://localhost:8412/styleguide.html>

Именно сервер, не `file://`: спрайт иконок подключается через `<use href="…">`,
словари грузятся `fetch`, а модули — ES-модулями. По `file://` браузер это заблокирует.

Целевые разрешения — 1280×720 … 1920×1080, базовый макет 1366×768 (§3.1).
Мобильных брейкпоинтов нет: это десктопное рабочее место.

> **Отладка: кеш ES-модулей врёт.** `python3 -m http.server` не шлёт
> `Cache-Control`, браузер кеширует модули эвристически, и правка в файле не
> видна на экране даже после F5 — можно полдня чинить уже починенное. Либо
> открывайте с `Cmd+Shift+R`, либо поднимайте сервер с `no-store`.

## Проверки перед коммитом

```bash
./tools/check-syntax.sh      # разбор всех модулей как ESM
python3 tools/check-contrast.py   # §4.4 + §9, считает из tokens.css
```

> **`node --check file.js` для этого проекта бесполезен.** Он разбирает файл как
> скрипт и **молча выходит с нулём**, пропуская даже пропущенную скобку. Цена
> несоразмерна: модуль не парсится → `boot().catch(fatal)` не выполняется →
> показать «АРМ не запустился» некому, и оператор видит пустую белую страницу.
> `check-syntax.sh` копирует файл в `.mjs` и разбирает как модуль. Скрипт
> проверен на живой ошибке, а не «должен работать».

### Проверено вживую в браузере, а не вычитано в коде

- полный сценарий §13: вход → F2 → QR → согласие → поиск → скоуп → форма →
  скан → PDF → завершение → пустой idle;
- **отзыв согласия** в сессии → интерстишл + wipe: ФИО и ИНН не находятся ни в
  DOM, ни в памяти, скоупы на «сервере» → 0;
- **TTL под замком** → замок остаётся, данные стёрты, разблокировка ведёт на
  пустую главную (раньше здесь было исключение — см. ниже);
- 403 на невыданный скоуп: в ответе нет тела, вкладка пустая, а не заблюренная;
- отправка заблокирована без обязательных документов, разблокируется после скана;
- форма проходится Tab + Ctrl+Enter без мыши; валидация не пускает пустое поле;
- смена языка в сессии не роняет приём: таймер и данные на месте;
- 1280×720 — без горизонтального скролла на всех экранах; на 1366×768
  «Завершить приём» на S8 видно без прокрутки;
- рефреш из активной сессии → S0, память и DOM чисты.

### Проверено вживую по итогам И1–И4

- **услуга без формы** («Замена паспорта») проходится до S8 на форме-заглушке;
- **«скоупы в памяти = выданные»** держится по ходу прогрессивной выдачи
  (3=3 → 4=4 → 6=6) — строка аудита в демо-панели;
- **пенсионная справка печатает лист без состава семьи**, справка о составе
  семьи — с ним: превью S8 ходит через `citizen.get()` по скоупам услуги;
- **под замком** пороги TTL 5:00/1:00 и TTL=0 не открывают ни модала, ни
  тоста (проверено на ×60); «Время приёма вышло» показывается после re-auth;
- **из `LOCKED` демо-панель больше не предлагает `LOCK`** — точка возврата цела;
- **шелл не уезжает**: на форме S6 прокрутка канваса до конца оставляет
  topbar на `top: 0`, таймер и «Завершить приём» видны;
- **возврат S7→S6** возвращает введённое молча, без баннера «восстановить
  черновик?» и без лишнего клика;
- **офлайн на форме** даёт банер «Нет связи с реестром» и честные чипы
  «введено» вместо пустых полей с чипом «из профиля»;
- **в таджикском интерфейсе** сбой сети даёт «Бо сервер алоқа нест», а не
  русский `message` из мока.

## Что здесь легко сломать обратно

Девять правил. Каждое написано после того, как соответствующая ошибка была
допущена и найдена — не из осторожности.

**1. Словарь на старте — фатален, в рантайме — нет.** `initI18n()` намеренно
пробрасывает ошибку, `setLang()` намеренно её глушит. Без словаря на старте
интерфейс вырождается в ключи разработчика («login.submit»), и оператор получает
рабочее с виду место, набранное отладочным мусором. А переключение языка не
должно стоить ему смены. Не «упрощайте», сделав поведение одинаковым.

**2. Фокус ставится синхронно, без `requestAnimationFrame`.** rAF не выполняется,
пока вкладка не отрисовывается: заблокировать АРМ (Ctrl+L) и сразу уйти в другое
окно оператор может запросто, и фокус в замок молча не встал бы.

**3. Ниже `return` в render-функции — только `function declaration`.**
`const fn = () => …` не поднимается и навсегда остаётся в TDZ; первый же вызов
падает «Cannot access before initialization». Ошибка выглядит как «экран просто
не заполнился»: promise отклоняется молча, в консоли пусто.

**4. Кнопка `type="submit"` обязана лежать ВНУТРИ `<form>`.** Снаружи она ни с
чем не связана и просто не работает — при этом выглядит нормально. Поэтому
колонка формы S6 — это сам `<form>`, вместе со sticky-футером.

**5. Скроллится `#screen`, а не документ.** Шелл фиксирован высотой вьюпорта
(§3.2). Вернуть `.shell { min-height }` и снять `overflow` со `#screen` —
значит вернуть Д-08: на форме S6 документ уедет целиком вместе с таймером TTL
и «Завершить приём», то есть с тем, что P3 требует держать видимым всегда.

**6. Новые слои под замком не открываются.** `#layers` и `#toasts` лежат вне
`#shell`, и `inert`/blur замка на них не действуют. Любой новый модал или тост,
который может сработать по таймеру, обязан пройти через `deferUnderLock()` в
`session.js` — иначе он окажется кликабелен поверх запертого экрана. Так уже
было с «Продлить приём?»: замок обходился модалом, который сам же и вызвал.

**7. Ошибки рендерятся через `errText(e)`, а не `e.message`.** Тексты
`ApiError` захардкожены по-русски; `message` — только фолбэк для кода, которого
ещё нет в словаре. Один `e.message` в новом экране = русская ошибка в
таджикском интерфейсе, и заметят её в самый неудобный момент.

**8. Распознавание не перетирает правку оператора (S2b).** `fill()` пропускает
поля с `dataSource === 'manual'` и непустым значением. Снять этот пропуск —
значит вернуть ошибку OCR в поле, которое оператор уже исправил: он правит
«ШBКД» → «ШВКД», досканирует прописку, и латинская `B` возвращается. Заметить
это на экране нечем — значение выглядит правдоподобно и уходит в реестр.

**9. Паспортные данные S2b не кладутся в `store`.** До `ENROLLED` сессии нет, а
`patchSession()` вне `SESSION` падает (§2.3.1). Единственное место заполненного
паспорта — замыкание `enroll.js` и его DOM. Соблазн «а давайте сохраним черновик
регистрации, чтобы не терялся» ломает ровно ту гарантию, ради которой всё
остальное написано: черновик переживёт экран.

## Архитектура: три границы, которые держат приватность

Гарантия §2.3 не держится на аккуратности экранов. Она держится на том, что
неправильное действие **невозможно**:

- **`storage.js`** — белый список ключей. Чужой ключ бросает исключение, а не
  предупреждение. Данные гражданина в localStorage не попадут физически.
- **`store.patchSession()`** — отказывается писать данные гражданина вне
  `SESSION`. Это не переход машины (§2.2 не знает события «черновик сохранён»),
  а запись данных, и держать её в таблице переходов значило бы соврать про
  машину: `legalEvents()` начал бы предлагать «сохранить черновик» как переход.
- **`mock/api.js`** — выданные скоупы живут «на сервере», а не в store. Иначе
  `citizen.get()` спрашивал бы разрешение у того, кто хочет данные, и 403 из
  §6/S5 был бы декорацией. Обойти его из UI нельзя.
- **`citizenSlice()`** — сервер отдаёт **срез** гражданина по выданным
  скоупам, и в `session.citizen` физически нет ключей, которых не выдавали.
  До И2 в память приезжал `CITIZENS[0]` целиком: экраны вели себя прилично,
  но гарантия держалась на их вежливости, а не на отсутствии данных. Теперь
  инвариант «скоупы в памяти = скоупы выданные» держится в обе стороны и
  показывается строкой аудита в демо-панели.

Плюс `wipe()` привязан к **событию** (`END_CONFIRMED`, `TTL_0`, `REVOKED`,
`CANCEL`), а не к состоянию. Прежнее правило «стираем на выходе из SESSION»
выглядело эквивалентным и молча ломалось там, где §6/S9c разрешает сессии жить
дальше: TTL, истёкший под замком, шёл `LOCKED → LOCKED`, из набора не выходил —
и данные оставались в памяти запертого рабочего места.

## Демо-панель (§11.5)

Клавиша `` ` `` — открывается с любого экрана, **включая вход**: демо-сценарий
§13 начинается именно там. Не перехватывается только в поле пароля и в textarea.

Три группы, и разделение осмысленное:

1. **Легальные события (§2.2)** — кнопки строятся из `store.legalEvents()`,
   поэтому панель физически не может предложить нелегальный переход. Машина
   дёргается «в лоб», без анимаций экрана.
2. **Гражданин (приложение)** — появляются, только когда гражданина реально о
   чём-то спросили, и отвечают экрану, который ждёт. Через эту дверь проходят
   тайминги и церемонии §6/S3. Пустая группа честнее полной.
3. **Сбои (§7)** — семь тумблеров: сеть, реестр, сканер, принтер, push,
   размытый скан, «OCR не распознал». Каждый = строка матрицы §7. Случайный
   сбой воспроизвести нельзя, а §13 требует воспроизводимости.
   «Сбросить всё» откатывает и реестр граждан: без этого второй прогон
   демонстрации S2b упирается в собственный результат первого («ИНН уже
   занят»).

Там же живой **аудит приватности**: память, localStorage, sessionStorage,
cookies, URL, ФИО в DOM, выданные скоупы на «сервере». Гарантию можно
**показать** стейкхолдеру, а не пообещать.

`×10` / `×60` ускоряют все таймеры (`clock.js` — единственный источник времени),
включая автоблокировку: иначе порог 5:00 у получасовой сессии не показать,
не просидев двадцать пять минут молча.

## Как читать токены

Компоненты берут **только** переменные, никаких hex (§11.2). Три правила,
которые чаще всего нарушают:

- **Текст-действие — всегда `--blue-ink`, не `--blue`.** `--blue` на белом даёт
  3.5:1 — он разрешён только для заливок кнопок и крупных элементов (§9).
- **На подложке `--h-*-bg` — только парный `--h-*-fg`.** Не сырой `--blue`/`--red`.
- **«Бумага» (`--qr-paper`, `--doc-*`) не переопределяется в тёмной теме, и это
  не недосмотр.** Тема — свойство рабочего места; QR-код и лист документа —
  свойства внешнего мира. QR сканирует камера гражданина, справка уйдёт в
  принтер на белом. Показывать тёмную версию того, что напечатается светлым, —
  значит врать про результат.

Типографика: специмен в Figma нарисован в масштабе **1.5×**. В коде — реальные
размеры (специмен ÷ 1.5): H1 44, H2 24, H3 17, Body 15, Label/Small 13, Caption 12.
Если сверяете с Figma и цифры «не сходятся в полтора раза» — дело в этом.

Шрифт ALS Hauss Next VF: лицензия на веб не подтверждена (§14), сейчас работает
фолбэк Inter. Метрики менять не нужно — стек уже прописан в `base.css`.

## Контраст (§4.4, §9)

Шесть светлых `--h-*-fg` затемнены до 4.5:1 — принят вариант 1 из плана
(`tools/fix-contrast.py`: двигает только светлоту в OKLCh, оттенок и насыщенность
держит, сдвиг глазом не читается: `#c9405e` → `#c13858`). Все 14 hue-пар и
текстовые пары §9 берут порог в обеих темах.

**От дизайн-лида нужно не решение, а сверка:** перенести шесть значений в Figma,
чтобы макет и код не разошлись. Код здесь забежал вперёд сознательно — без
этого Ф3–Ф6 упирались в открытый вопрос без дефолта.

Проверка живёт в двух местах и обе считают из `tokens.css`, а не хранят цифры:
`tools/check-contrast.py` и раздел «Категории услуг» в витрине (пересчитывается
при смене темы). Захардкоженный отчёт устаревает молча — именно так §4.4 и
прожила версию 1.0 с неверным утверждением «пары выверены на AA».

## Пересборка ассетов

Оба скрипта детерминированы и воспроизводят файлы байт-в-байт.

```bash
# Спрайт иконок из tools/icons-frame.svg (выгрузка фрейма Icons, node 15-4).
python3 tools/build-sprite.py

# Плейсхолдер QR (не настоящий код — заглушка для вёрстки S2)
python3 tools/build-qr-placeholder.py
```

`build-sprite.py` падает с внятной ошибкой, если имена разошлись с §4.3, иконка
уехала из своей ячейки, остался литеральный цвет или результат не парсится как XML.
Последнее — не теоретическое: `girih-tile` заворачивает пути во вложенный `<g>`,
и наивный разбор «до первого `</g>`» делал нечитаемыми все 25 символов после него.

`assets/icons.svg` **руками не править** — правки затрёт следующая пересборка.

Использование: `<svg class="icon"><use href="assets/icons.svg#i-qr"/></svg>`.
Размеры: 24 (по умолчанию), `.icon--20` (кнопки M/S), `.icon--16` (чипы),
`.icon--48` (пустые состояния). Цвет — через `currentColor`.

> Имя `dash` в §4.3 обманывает: в спрайте это dashboard (сетка из квадратов),
> а не прочерк. Для «ожидает» берите `clock`.
